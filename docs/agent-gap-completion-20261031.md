# Agent Coding 剩余功能补齐（2026-10-31 至 2026-11-01）

本批继续完成[上一批分析报告](agent-coding-improvements-20261031.md)列出的主要功能差距。当前实现以本报告为准；旧报告的 660 项结果是修改前基线。真实模型使用、页面点击和视觉验收由用户完成。

## 功能变化

### 每任务独立执行目录

桌面新建 Code 任务默认使用独立工作区。Git 项目使用原生 worktree 和独立 `codex/task-*` 分支；普通文件夹使用任务副本。复制当前可编辑文件状态，包括暂存、未暂存、未跟踪文件；原目录分支和暂存区不变。密钥、受保护路径、生成目录、符号链接及 Windows junction 不复制，依赖目录不建立链接。

任务保存来源目录与执行目录两个 ID。侧栏按来源分组，新任务使用来源 ID；读取、补丁、测试和 Git 操作使用执行 ID。页面显示两个目录的位置。API 旧调用默认保留直接目录行为，可通过 `isolated_workspace: true` 选择隔离。

命令启动前保存源码字节及摘要，备份在任务执行目录外持久化。命令结束后收集创建、修改、删除的文本差异，恢复原字节，再通过已有 PatchService 预览、确认、应用和检查点流程。命令草稿跨重启保存；恢复时原文件、摘要或归属不完整会拒绝写入。源码检查仍检测原目录、执行目录和 Git 状态变化；Git 元数据漂移不自动回写。

Git worktree 与来源仓库共用本地 Git 配置。命令前后同时比较源码、分支、HEAD、暂存区和本地 Git 配置；共享配置发生变化也会阻止继续生成或应用改动。源码恢复不会自动覆盖 Git 配置，需人工审阅并处理这类漂移。

工作区创建期间会先保存来源归属。若重启发生在工作区记录已保存、任务尚未绑定的阶段，只为首轮尚未开始且等待计划确认的任务补齐执行目录绑定，仍须明确恢复。创建记录缺失、已执行任务的绑定不一致或托管目录缺失时，恢复和后续写入均被阻止，不会退回来源目录执行。来源文件夹列表仍可使用，用户可恢复原托管目录，或删除残留任务；删除不影响来源文件。

删除任务会清理其托管执行目录和状态；删除来源目录登记时，有关联任务必须明确级联。完成任务会保留执行目录与完成证据。原目录文件不会因任务删除而被删除；Git 的任务分支保留，避免丢失已有提交。

Python 验证优先使用执行目录的环境；没有环境时可使用来源项目相应目录的 `.venv/venv` 解释器，进程工作目录仍是任务执行目录。Node 等依赖需在执行目录准备，避免共用可写依赖目录。

### 大文件按行读取和精确修改

模型 `read` 请求支持 `start_line/end_line`。每个文件保留最新读取区段，提示原始行号、总行数和未读边界。区段更新必须使用 `old_text/new_text`，只能修改已读范围内的唯一匹配；不能用完整替换或删除覆盖未读内容。

区段关联完整读取原文和完整文件 hash，最终生成完整 PatchFile，继续使用预览时的原文保护。未读区域的重复文本不影响区段内匹配，CRLF 与未读内容保持原样；任何外部文件漂移仍使预览失效。读取与补丁仍受原文件大小限制，区段功能不取消保护上限。

按目标路径加载根到目标父目录的适用 `AGENTS.md`，在上下文裁剪时优先保留。规则文件无法安全读取或无法供给时停止修改。TS/JS ESM 的 `.js/.jsx/.mjs/.cjs` 路径在原文件不存在时回退对应 TypeScript 源文件；这仍是有限关联，没有新增持久索引。

### 需求步骤和完成证据

输入包含至少两项明确编号、项目符号或中英文分号分隔要求时，直接按列项建立子目标，原始目标和说明头保留。最多支持 12 项，每项最多 500 字；超过限制明确拒绝创建，不截断要求或保存半个任务。步骤标题最多展示 120 字，完整要求保留在说明与自动完成条件中。非结构化文本或单项要求仍使用现有计划模板。

执行前可以编辑步骤标题、说明、涉及文件、风险和验证方式。每步至少绑定一项完成条件；删除步骤会移除其绑定条件，保存后的整个计划参与审批 hash。首轮开始后锁定计划，原任务目标仍保留。

修改步骤时，与原步骤同步生成的完成条件随标题或完整要求更新；用户自行改写的条件保留。保存初始模板也会为每步绑定条件，需先保存确认再开始执行。

运行中展示步骤对应的实际改动、迭代和完成证据。文件归属依据计划中声明的路径和真正应用过的补丁；回滚迭代不累计，验证或完成确认过期会降低对应状态。没有声明文件的步骤不虚构改动归属，完成需要人工证据。

### 普通目录和无需改动的本地完成

模型可以明确返回 `no_changes: true` 与理由，与编辑或上下文请求互斥。该结果仅将当前迭代转入验证，不生成空检查点，也不自动完成。

当前文件通过全部必要检查后，用户逐项确认绑定当前计划、迭代和验证 hash 的证据，再点击“本地完成”进入 `completed`。旧任务没有完成条件时，需要明确提供 `task-goal` 的原目标证据。暂停、取消、恢复未确认、回滚、验证过期或阻塞状态均不能通过完成门禁。

### 验证结果与发布范围

独立工作区会保留来源目录原有的可编辑未提交文件，测试可能依赖这些文件。若这类文件未进入当前任务的提交范围，即使全部检查通过，也会阻止手动提交、自动提交和远端发布。提交预览通过 `scope_blocked_files` 列出受影响文件，并禁用写入审批与提交入口。用户需先审阅处理这些改动，或在完整验证与完成证据确认后选择“本地完成”。

## 使用顺序

1. 在来源目录新建 Code 任务，核对页面显示的来源与执行路径；在执行目录准备项目依赖。
2. 执行前编辑并保存计划步骤、涉及文件、必跑检查和完成条件；修改计划后重新确认审批范围。
3. 审阅模型补丁或命令产生的差异，确认后应用；命令草稿恢复前先确认任务恢复，冲突或备份损坏时按提示处理。
4. 查看逐步骤改动与检查结果，在当前验证通过后逐项填写完成证据。普通目录、无需改动或暂不发布的任务可选择本地完成。
5. 需要 Git 提交时先核对提交预览；范围外未提交输入必须处理后重新验证。完成任务保留执行目录，后续新任务从来源目录创建。

## 使用边界

独立工作区提供任务文件归属与恢复，不是操作系统沙箱。命令仍在主机用户权限下执行；绝对路径、外部写入、受保护路径及所有 Git 共享元数据不在源码快照的完整覆盖范围。

明确列表使用有限规则拆分，其他需求的计划初稿保留现有模板，支持编辑和证据追踪；没有用模拟测试证明复杂需求理解、自动拆解质量或真实模型成功率。真实业务覆盖仍依赖项目检查清单和人工需求验收。页面检查是组件和回调级验证，真实点击与视觉结果仍待用户验收。

生产构建通过，当前主 JS 产物为 509.23 kB（gzip 150.26 kB），Vite 提示超过 500 kB。该提示不阻止构建；首屏性能需结合真实桌面使用评估后再决定是否拆包。
