- [ ] 上下文路径可点击进入文件浏览，显示最近读取的时间/轮次；清楚区分当前待发送附件与上次实际模型请求上下文。
- [ ] 在现有预算中补齐时长、连续失败、具体耗尽原因和对应下一步；让附件发送后的记录可核对文件名和大小。
- **依据：** [ChatPanel.tsx](../apps/desktop/src/components/ChatPanel.tsx) 的 286–288 行把文本附件拼入消息，354–365 行展示最近上下文的静态路径及部分预算；[AgentPanel.tsx](../apps/desktop/src/components/AgentPanel.tsx) 的 134–150 行已有完整预算展示。
- **验收：** 点击路径定位到本次实际读取的文件；切换任务不混用上一任务数据；不把字符数、文件字节数或调用预算伪装成 token 使用率。Provider 尚未返回 token 用量时明确缺少该数据。

## P2：能力评估与交付

### T10 — 固定任务评测与上下文优化

- [ ] 固定 5–10 个有明确原测试和完成条件的任务，覆盖单文件修复、跨文件依赖、monorepo、已有失败、普通目录和有界停止；每次版本记录成功率、人工介入、调用数、耗时和上下文字节。
- [ ] 针对评测中的具体失败改进关联文件选择与跨轮证据保留；先给 Cowork 长历史设置明确预算，再考虑压缩，保留原始审计记录。
- **依据：** 目前已有显式路径、失败位置和有限关联上下文，历史真实模型样本是 3 类；[agent_service.py](../apps/api/app/agent_service.py) 的 796–800 行 Cowork 按历史事件组装消息。已有调用次数限制不等同于历史消息大小限制。
- **验收：** 每个样本能重复执行且原测试未被改弱；报告区分环境阻塞与模型失败；选取或压缩改进能在同一组任务中证明效果，不只凭主观判断。

### T11 — 桌面安装包与干净环境启动

- [ ] 选择一种明确的 Python/API runtime 交付方式，补 Windows 打包及安装配置；检查状态、日志、模型配置和升级后的数据位置。
- **依据：** [main.cjs](../apps/desktop/electron/main.cjs) 的 76–85 行打包版没有内置 API，当前桌面仍依赖源码和 Python 环境。
- **验收：** 无项目源码和开发虚拟环境的 Windows 环境能安装、启动、配置模型并完成普通目录的本地任务；重启保留数据；启动失败给出实际可执行的修复信息。

### T12 — 自动回归与 CI 结果接入

- [ ] 建立最低必要的项目 CI：API 测试、前端类型检查、聊天组件检查和构建，失败时保留可定位的日志/JUnit。
- [ ] 之后再给产品接入 PR 的 CI 状态和失败日志定位，复用现有发布快照与审批规则。
- **验收：** CI 在隔离状态下可重复运行；产品显示明确的检查名、对应提交和错误位置。自动修 CI、多仓库协调、Review 自动回复和自动合并不作为这一阶段的前置目标。

## 建议执行顺序

1. T01 / T02 / T03：先复现状态、模型和桌面运行风险，成立后做最小修正并补回归。
2. T05：补齐执行前检查入口，确保新界面能使用现有验收能力。
3. T04：在最终实现上跑完整后端回归和真实桌面操作，更新当前侧栏截图。
4. T06 / T07 / T08 / T09：完善状态、Cowork、结果阅读和上下文交互；每项使用真实 API 场景验证。
5. T10 / T11 / T12：以任务评测驱动能力改进，再完成安装分发与 CI 接入。

首轮交付标准是：用户从聊天页发起本地 Code 任务，能准确配置验收、看到真实状态、完成审阅与回滚；切换会话、停止或 API 重启不会污染输入、模型或磁盘结果。
