# 核心 Agent 修改复核（2026-10-24）

本轮复核覆盖工作区全部已跟踪 diff 和新增源码、测试文件，包括执行状态、目录互斥、模型上下文、验证保护、完成条件、发布快照、前端保存与轮询，以及文档的数据口径。真实点击按用户要求停止自动尝试，留给用户手动操作。

## 复现与修正

| 方向 | 原触发条件与问题 | 修正与回归 |
|---|---|---|
| 模型命令停止 | 停止、暂停或取消时，模型命令的后台线程尚未完成清理，目录占用已释放；手动起草的停止还可能继续下一次模型调用 | 命令启动前预留取消槽，复用验证的 worker 等待逻辑，重复取消保持目录占用；已取消的命令终止本次起草。新增 7 项取消、启动前停止、手动停止和 runner 故障用例 |
| 验证配置保护 | 保持 `tsc` 命令不变，把 strict 改为 false，可使真实 TS2322 错误变成通过而未触发保护 | 保护 TypeScript、ESLint 配置、所选脚本明确引用的 JSON 输入，以及有界的本地 `extends` 引用。新增 15 项配置、JSONC、循环引用和普通 JSON 数据边界用例 |
| 旧任务发布门禁 | 未设置完成条件的任务提交后，外部改弱测试文件，直接推送或创建 PR 仍可能被允许 | 推送、PR 预览与创建共享验证输入检查；未单独确认的验证变更阻断发布。新增 2 项直接入口用例，检查拒绝前没有远端副作用 |
| 保守模式准备入口 | 首次循环停在计划审批、尚无编码迭代时，历史 `agent.loop` 事件被误判为已开始，准备入口消失 | 依据实际迭代判断是否开始；计划待批时可以重开，正在执行和首轮已开始时关闭。真实组件检查覆盖三个状态 |

每项修改都先用红测试复现，再通过现有回归。没有新增依赖；本轮没有再次调用真实模型、浏览器或 GitHub 发布操作。

## 保留的边界

- 目录互斥作用于单个本地 API 进程，不是跨进程或容器隔离。

- 完成证据由操作者确认，服务端不会把一段文字自动判断为需求正确。
- 本轮真实点击未执行，不计为通过；隔离 API 与 Vite 已停止。

所有源码改动保留在工作区，没有提交主项目、部署或合并 PR。测试日志、JUnit 和审计清单保留供复核。
