## 后续优先级

### P0：完成交互验收

验证普通文件夹打开 → 浏览 → 标准模式修改 → 测试通过 → 本地审阅 → 回滚；另覆盖保守模式每轮确认、首次失败输入保留、停止与重启恢复。Git 根目录继续验证分支、精确提交和受控发布。

### P1：证明真实任务完成能力

- [ ] 一个真实模型完成单文件修复、两文件修改、一次测试失败后的修复，记录实际上下文与验证结果。
- [ ] 建立 5–10 个边界清楚的任务，统计独立验证通过数、人工介入次数、耗时和模型调用量。
- [ ] 在专用 GitHub 仓库实测人工审批 → 推送 → Draft PR → 状态刷新；git 凭据助手和 REST token 分别验证。离线测试继续使用 fake Provider。

### P2：有限扩展与交付

- [ ] 先读取 CI 状态与失败日志，再接少数明确类型的修复；Review 对话与复杂冲突不同时展开。
- [ ] Electron 补齐后端运行时与安装分发，确认新机器无需理解源码结构即可启动。

## 当前边界

单工作区根目录、单文件夹任务、单进程本地服务。Cowork 是附带可选目录摘要的聊天；计划仍由规则生成。测试命令运行在主机上，没有容器沙箱。远程 Provider 与模型客户端已有实现，离线工作流通过不等于真实模型/GitHub 已验收。

当前阶段保持 Code 本地修复为主线，不扩张通用办公 Agent、多仓库、技能市场或企业部署。
