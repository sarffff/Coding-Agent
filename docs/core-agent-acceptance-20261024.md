## 已完成的核心能力

- 执行按真实目录互斥，同目录和父子目录不能同时写入，独立目录可并行；停止、暂停和取消等待 worker 结束，迟到模型回复不落盘。
- 修改前验证单独保存，已有断言失败可进入修复，测试收集、配置、环境和超时阻塞先转人工；固定验证器并区分原有、新增和已解决的失败。
- 有界修复携带最近尝试与失败证据；可恢复的输出、上下文和预览错误在预算内重试，重复无效建议和没有新证据的修复转人工复核。
- 上下文优先读取仓库规则、显式路径和失败定位，补充有限关联文件；已找到目标文件后不再用无关应用文件填满预算。单行 `edits` 使用不带换行的最小唯一匹配，多行替换保留 CRLF 的精确换行。
- 已有测试、验证配置和所选脚本受保护。验收变更须单独审阅确认；普通补丁确认和删除确认不能代替验收确认，失败与回滚保留对应保护边界。
- 任务准备阶段编辑必跑检查和完成条件，未保存或保存中不能启动，失败重试复用原任务。首次迭代后条件锁定，变更条件会使旧计划审批失效。
- 完整改动复核修正保守模式的准备入口：首次循环停在计划审批且编码迭代仍为零时，可以重新编辑；历史 `agent.loop` 事件不会提前锁定。真实组件红测先复现过早关闭，修正后还验证了首轮开始和循环运行时保持关闭。
- 完成条件持久化并绑定原始目标；逐条证据必须由操作者显式确认，测试通过不会自动确认需求完成。确认绑定当前范围哈希、验证哈希和迭代，后续变更使旧确认失效，并阻止提交和发布。
- 提交绑定精确预览和写入审批；推送、PR 预览与创建共用发布快照校验，检查任务分支、已审批 HEAD、未提交任务改动及已推送 SHA。PR 预览展示相对目标分支的完整差异，远端操作使用独立审批、预算、幂等与审计记录。

完成条件上限为 12 条，每条文本最多 500 字符，证据最多 1000 字符。状态为 `not_required`、`pending`、`stale` 或 `confirmed`；空条件兼容已有任务。证据确认是人工复核记录，服务端不把文字说明自动判定为需求正确。

### 单文件修复与故障注入

真实模型首先修复 clamp 的边界行为。操作者在确认后注入错误，将正确返回式改为 `return value`，未改变测试；原确认再次提交被 `COMPLETION_CONFIRMATION_STALE` 拒绝。随后真实模型完成第二轮修复，原有三项测试通过，操作者重新确认当前迭代与哈希。

成功补丁审计记录的两文件上下文分别为 452 与 372 字节，模型起草耗时分别为 49.654 与 15.255 秒。故障注入由操作者实施，不属于模型未经请求引入的回归。

### 两文件修改与简化修订

任务覆盖 `normalizer.py`、`greeting.py` 及原有 `test_greeting.py`。首轮修改通过测试后，操作者指出重复执行 `.strip().capitalize()`，要求一次 normalization 并保留 greeting 行为与测试；第二轮简化通过原有三项测试后再次确认。

两次成功补丁的三文件上下文分别为 488 与 623 字节，起草耗时分别为 48.268 与 27.367 秒。该场景同时记录了功能验证和人工简化反馈。

### GitHub 独立夹具

原目标仓库是 React/Vite 应用，没有现成 pytest 入口。本轮在 `acceptance/core-agent-20261024/` 添加 `calculator.py` 与 `test_calculator.py`，先建立本地 seed，再让 Agent 在任务分支修复源码。初次上下文误带无关应用文件，共 119930 字节；补齐显式路径优先、找到目标后停止无关兜底的规则后，成功补丁只读取两个夹具文件，共 452 字节。真实模型共请求两次，首次超时，修正后第二次成功，起草耗时 11.430 秒。模型提示与编辑冲突反馈也补上最小唯一 `old_text` 和 CRLF 精确换行指引。原有低于下界、高于上界、区间内三项测试全部通过，并完成显式证据确认。
