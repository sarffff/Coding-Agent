# Phase 1 Todo：单仓库代码理解与低风险修改

> 目标：完成一个可运行、可审计、可恢复的最小研发闭环：
> **选择一个本地仓库 → 建立索引 → 理解代码 → 生成修改计划 → 执行低风险修改 → 运行本地测试 → 展示结果**。

## Phase 1 范围

### 纳入

- 单个本地 Git 仓库
- 只读代码浏览与搜索
- 基础文件树、符号和依赖信息
- 一个任务对应一个执行会话
- 低风险文件修改
- 本地单元测试与静态检查
- 操作轨迹、差异预览、检查点和回滚
- Desktop 端基础工作台

### 暂不纳入

- 多仓库任务
- 自动创建 PR、推送远程分支
- CI/CD 触发与修复
- 生产环境操作
- 大规模迁移
- 自动执行高风险命令
- 完整向量数据库和复杂调用图

## 交付节奏

建议周期：2–3 周。

| 周期 | 目标 | 可演示结果 |
|---|---|---|
| 第 1 周 | 仓库接入、索引、只读理解 | 选择仓库后看到文件树、搜索结果、项目摘要 |
| 第 2 周 | 任务规划、低风险修改、测试执行 | 输入任务后生成计划，修改文件并运行测试 |
| 第 3 周 | 审计、检查点、回滚、Desktop 联调 | 失败可恢复，所有操作可回放，完成端到端演示 |

## Phase 1 完成定义

以下场景全部成功，Phase 1 才算完成：

1. 用户在 Desktop 中添加一个本地 Git 仓库。
2. 系统展示仓库摘要、文件树和当前分支。
3. 用户输入一个小范围修改任务。
4. 系统返回计划，并列出涉及文件和验证命令。
5. 用户查看 diff 并确认应用。
6. 系统创建检查点并应用修改。
7. 系统运行本地测试并展示日志和结果。
8. 用户可以查看完整执行轨迹。
9. 测试失败时，用户可以回滚到检查点并恢复任务。

## Phase 1 风险控制

- 默认只允许本地 workspace 内的读写。
- 默认不联网，不推送远程，不创建 PR。
- 默认禁止删除文件、修改 `.git`、读取密钥文件和执行白名单外命令。
- 每次写操作必须先预览 diff，并在应用前创建检查点。
- 命令执行必须有超时、输出上限和取消能力。
