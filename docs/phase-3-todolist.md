# Phase 3 Todo：CI 交互、自动修复、冲突处理与完整治理

> 目标：把 Phase 2 的本地闭环延伸到远程与流水线，形成
> **推送任务分支 → 触发/读取 CI → 解析失败 → 生成修复轮次 → 处理冲突 → PR 收口**，
> 并用预算熔断、凭据治理和完整审计把它约束在可生产落地的范围内。

## 前置事实（写作时状态）

Phase 3 不能立即开工：Phase 2 的**远程段为 0%**，而 CI 交互依赖它。

| Phase 2 遗留 | 当前状态 | 对 Phase 3 的影响 |
|---|---|---|
| 持久化与重启恢复 | 全部状态在进程内存 | 无法承载跨小时的 CI 等待与重试 |
| 幂等键 | 未实现 | 推送/PR/触发流水线会重复产生副作用 |
| `RemoteProvider` 与推送 | 未实现 | CI 状态与日志来源缺失 |
| PR/MR 创建与查询 | 未实现 | 无收口对象 |
| 审批中心与 `push`/`pr` 决策 | 类型已定义、无执行入口 | 远程写操作无人审入口 |

因此第 0 节是 Phase 3 的进入条件，也是它的第一批工作项。

## Phase 3 范围

### 纳入

- 首个远程 Provider（GitHub 或 GitLab，二选一）的推送、PR 与检查状态读取
- CI 流水线状态订阅、任务日志拉取与结构化解析
- 常见失败的自动分类与修复轮次生成（复用 Phase 2 编码循环，不新造第二套循环）
- 合并冲突的检测、可自动解决类别的白名单处理与人工转交
- 任务级预算熔断：轮次、墙钟时间、工具调用、远程请求、diff 规模
- 凭据治理、敏感内容阻断与可配置规则
- 完整可回放的审计（按任务/运行/轮次/提交/PR 查询）
- Desktop 的 CI 面板、审批中心、预算视图与冲突视图
- 面向 Provider 的契约测试与可重复演示流程

### 暂不纳入

- 生产环境部署、回滚与运维操作
- 自动合并 PR、自动关闭 Issue
- 强制推送、删除远程分支、改写受保护分支历史
- 多仓库与跨仓库 PR
- 任意语义冲突的自动解决
- 第二个 Provider（保留抽象，不做实现）
- 完整向量检索与复杂调用图

## 交付节奏

建议周期：4–6 周。

| 周期 | 目标 | 可演示结果 |
|---|---|---|
| 第 1 周 | Phase 2 遗留收口：持久化、幂等键、恢复语义 | 重启 API 后任务与审批可查，重复请求无重复副作用 |
| 第 2 周 | Provider 抽象、推送与 PR 草稿 | 任务分支被推送并生成 Draft PR |
| 第 3 周 | CI 状态读取、日志解析与失败分类 | PR 上每个检查的结论与失败原因可读 |
| 第 4 周 | 修复轮次与预算熔断 | 常见失败自动生成下一轮，超预算即转人工 |
| 第 5 周 | 冲突处理与审批中心 | 可自动解决的冲突走白名单，其余转人工 |
| 第 6 周 | 治理收口、端到端演示与发布门槛 | 一条可重复的 Issue→PR→CI 绿→待合并演示 |

## Todo 清单

### 0. 状态持久化与恢复（Phase 2 §6 遗留）

- [ ] 将仓库、任务、轮次、检查点、审批与审计事件写入本地持久化存储
- [ ] 为写接口增加幂等键：相同键的重复请求返回首次结果，不重复执行副作用
- [ ] 服务重启后未完成任务标记为“需人工确认”，禁止静默续跑
- [ ] 为测试输出、Patch 与日志设置大小上限与保留期限
- [ ] 提供本地开发初始化与迁移命令，并写入 README

**验收标准**

- 重启 API 后能查询历史任务、审批、提交与关键事件。
- 同一幂等键重复提交不产生第二个分支、提交或 PR。
- 重启后没有任何任务在无人确认的情况下继续执行。

### 1. Provider 抽象与远程写操作

- [ ] 定义 `RemoteProvider` 接口：仓库识别、分支、提交、推送、PR 创建与查询、检查状态
- [ ] 从远程 URL 解析平台、owner 与仓库名，拒绝未配置的平台与任意 URL
- [ ] 推送只允许任务分支，禁止强制推送与删除远程分支
- [ ] 推送前校验本地 HEAD 与远程分支祖先关系，落后即停止并要求恢复
- [ ] 处理远程分支已存在、认证失败、权限不足、网络超时与限流
- [ ] 记录提交 SHA、分支、远程摘要与推送结果，不记录凭据

**验收标准**

- 未推送通过 `push` 审批的任务分支不会被推送。
- 推送失败不误报成功，任务停在可重试状态并保留审计事件。
- 用户未提交的本地工作不会进入任务提交。

### 2. CI 状态读取与日志解析

- [ ] 定义 `PipelineRun`、`PipelineJob`、`PipelineLog`、`CheckConclusion` 数据模型
- [ ] 按 PR 拉取检查/流水线状态，保存 provider id、结论、链接与时间戳
- [ ] 长轮询或回调订阅状态变化，写入审计事件并可按任务查询
- [ ] 拉取失败任务日志并截断，区分 `lint`、`type`、`test`、`build`、`flaky`、`infra`、`timeout`
- [ ] 从日志中提取文件、行号、测试名与错误摘要，关联到具体轮次与提交
- [ ] 识别基础设施类失败（拉取镜像失败、runner 掉线、配额超限），不进入自动修复
- [ ] 处理日志缺失、流水线被取消、状态长时间不返回

**验收标准**

- PR 上每个检查的结论、来源与耗时在 Desktop 可读。
- 失败能定位到文件、行号或测试名，并说明属于哪一轮、哪个提交。
- 基础设施失败被分类为不可自动修复，直接转人工。

### 3. 常见失败自动修复

- [ ] 复用 Phase 2 编码循环处理 CI 失败：新建轮次、预览 Patch、审批后应用、重跑验证
- [ ] 定义可自动修复白名单：格式与 lint 规则、缺失依赖声明、导入顺序、快照与 lock 文件、明确的断言失败
- [ ] 定义必须转人工黑名单：安全告警、依赖漏洞、测试被跳过、契约变更、覆盖率下降、超时
- [ ] 修复建议必须附带失败证据（日志片段、文件行号）与预期验证命令
- [ ] 应用修复前重新预览 diff，且重新绑定 `scope_hash`
- [ ] 每轮修复记录假设、改动、验证结果，供回放与效果统计
- [ ] 连续失败达到阈值后停止自动动作并进入人工审批

**验收标准**

- 一次 CI 失败可以在无人工改代码的情况下完成“修复→推送→CI 转绿”。
- 白名单外的失败一律不自动修改，且给出转人工原因。
- 自动修复不会删除或跳过测试来让流水线变绿。

### 4. 合并冲突处理

- [ ] 创建或更新 PR 前检测任务分支与基础分支的可合并性
- [ ] 在隔离工作副本中试合并，不在用户工作区留下冲突状态
- [ ] 定义可自动解决的冲突白名单：lock 文件、生成物、纯追加的配置项
- [ ] 语义冲突不自动解决：产出冲突文件、双方 diff 与建议方案后转人工
- [ ] 自动解决后重新运行完整验证，并要求新的 `push` 审批
- [ ] 基础分支更新后允许重新同步（rebase 或 merge 二选一，且策略可配置）
- [ ] 记录冲突解决前后内容，保证可回滚

**验收标准**

- 冲突场景下用户能看到冲突文件、双方内容与建议，并选择方案。
- 自动解决只发生在白名单内，且解决后重跑验证并重新审批。
- 任何情况下都不出现强推或受保护分支被改写。

### 5. 预算与熔断治理

- [ ] 定义任务级预算：最大轮次、墙钟时间、工具调用次数、远程请求次数、diff 规模
- [ ] 在状态机每次转换处校验预算，超限即停止自动动作并转人工审批
- [ ] 审批界面显示已消耗与剩余额度，提高上限需要显式审批并留痕
- [ ] 限制并发：同一仓库同时只允许一个写任务，同一 run 只允许一个验证进程
- [ ] 预算耗尽或超时后保留已完成部分与检查点，不清空、不静默重试

**验收标准**

- 达到任一上限时任务进入人工状态，且审计事件说明触发了哪一条。
- 提高上限的操作可追溯到具体审批人与时间。
- 并发写任务不会互相覆盖工作区。

### 6. 审计、可观测与效果度量

- [ ] 为每个轮次与远程调用记录开始、结束、耗时、输入摘要、输出摘要与结果
- [ ] 审计事件支持按任务、运行、轮次、提交和 PR 查询
- [ ] 记录 Provider 请求耗时、状态码与重试次数，不记录令牌与敏感响应
- [ ] 提供一次任务的完整回放视图（计划→Patch→测试→审批→提交→推送→CI→PR）
- [ ] 建立效果指标：CI 修复成功率、误修率、人工介入频率、平均完成时长、PR 合并率
- [ ] 建立失败场景数据集，用于回归验证自动修复质量

**验收标准**

- 任一任务可完整回放到每个远程操作与其结果。
- 响应丢失或超时后有对账路径，不盲目重复副作用。
- 效果指标可产出数字，而不是只有日志。

### 7. 安全与凭据治理

- [ ] Token 只经环境变量或系统凭据存储注入，禁止进入日志、数据库、Patch、提交与 PR 正文
- [ ] 提交前扫描 diff 与文件内容，阻断密钥、令牌、证书与高熵字符串
- [ ] 把内置的敏感路径判定改为可配置规则，并允许仓库自定义忽略与阻断清单
- [ ] 远程调用只允许配置的 Provider 与仓库白名单，禁止任意 URL 请求
- [ ] 输出 Provider 最小权限说明与凭据轮换说明
- [ ] 明确高风险操作（强推、删分支、改受保护分支、合并 PR）在本阶段全部禁用

**验收标准**

- 含密钥的 diff 在预览与提交两处都被阻断，并留下审计事件。
- 日志与数据库中检索不到任何凭据形态的内容。
- 未配置的外部地址无法被请求。

## Phase 3 完成定义

以下场景全部成功，Phase 3 才算完成：

1. 任务分支通过 `push` 审批后推送成功，并生成 Draft PR。
2. 系统读取到 PR 的检查状态，并把失败分类为可修复或需转人工。
3. 可修复失败自动创建下一轮，预览 Patch，经审批后应用并重新验证。
4. 修复推送后 CI 转绿，PR 展示最新提交、检查结果与测试摘要。
5. 基础分支更新导致冲突时，白名单冲突自动解决并重跑验证，语义冲突转人工。
6. 连续失败或预算耗尽时自动动作停止，任务进入人工状态且保留检查点。
7. 服务重启或响应丢失后，任务可查询、可恢复，且不产生重复提交或重复 PR。
8. 一次任务从计划到 PR 的完整轨迹可回放，其中不含任何凭据。
9. 演示脚本可在干净仓库上重复执行，并可一键清理分支。

## Phase 3 风险控制

- 远程写操作只在显式审批后执行，默认创建 Draft PR 且不自动合并。
- 禁止强制推送、删除远程分支、改写受保护分支与自动关闭 Issue。
- 自动修复仅限白名单失败类型；不可修复类型与基础设施失败直接转人工。
- 任何自动修复都必须重新预览 diff、重新审批、重新验证。
- 预算与并发上限触发后停止自动动作，不允许静默提高上限。
- 凭据只经环境注入，任何输出与存储都必须先脱敏再截断。
- 远程调用目标受 Provider 与仓库白名单约束，禁止任意 URL。
- 每次远程副作用都必须有幂等键与可查询结果。
