# 聊天功能补齐（2026-10-31）

本批补齐 Cowork 流式回复、已发送附件、会话管理、持久草稿和聊天内差异预览。真实使用与视觉验收由用户完成；本地验证使用实际组件、受控回调、模拟 Provider 和隔离 API 测试，不调用真实模型，不执行真实 HTTP 或窗口点击。

## 已完成

| 使用场景 | 当前行为 |
| --- | --- |
| Cowork 回复 | 使用真实 Provider 流式接口逐段展示正文；支持停止、失败提示和同请求重试。截断、提前断流或缺少完成帧时，不把部分回复标为成功 |
| 已收到回复但记录刷新失败 | 保留已收到的完整回复，继续发送时仍显示上一条；记录恢复后按请求 ID 去重。旧刷新结果不能抹掉较新的审计消息 |
| 核对已发送附件 | 用户消息展示文件名、UTF-8 字节数和可展开原文，重新打开会话仍可查看。旧记录没有结构化元数据时保留原正文，不猜测解析 |
| 查找会话 | 当前 Cowork/Code 轨道内按会话名称搜索；Code 也支持文件夹名称和路径，保留原有分组及删除入口 |
| 重命名会话 | 名称保存到本地 API；支持键盘保存、取消、失败重试和重复提交保护。原始任务目标、计划和验收范围保持独立，迟到响应不能重新插入已删除会话 |
| 恢复草稿 | 文本、完成条件和待发送附件保存在本机，按 API 实例、会话及目录隔离；新建会话使用唯一身份，创建任务后迁到任务 ID，包括已切换到别的会话时的迟到回包 |
| 删除与迟到回调 | 删除任务同时清理任务草稿、逻辑别名、临时回复和重试状态；迟到输入不能重新保存已删草稿，删除目录的回包不会覆盖期间切换到的新会话 |
| 查看本轮差异 | 从聊天执行摘要展开当前轮次的检查点差异，按运行 ID 和检查点 ID 匹配；按需加载、支持失败重试，回滚后明确显示历史改动 |

复用现有主题、原生流读取、附件拼接和检查点接口，没有新增依赖。搜索、重命名、附件、差异和中断提示补齐中英文、键盘焦点与长内容局部滚动。

## 接口与兼容

- 保留 `POST /api/v1/tasks/{id}/chat`；新增 `POST /api/v1/tasks/{id}/chat/stream`，提供 `start`、`delta`、`done`、`error` SSE 帧，每帧带请求 ID。
- OpenAI 使用 Chat Completions 流式协议，Anthropic 使用 Messages 流式协议；两者均确认终止原因，输出长度截断不能落成功助手记录。没有流式能力的 Provider 返回一次完整回复，不模拟打字。
- 创建任务和发送消息可附带 `message_text` 与 `attachments`，服务端核对它们与原有完整消息一致，再保存审计。原客户端可以继续仅传完整正文。
- 新增 `PUT /api/v1/tasks/{id}/name`，修改 `display_name`，不替换原 `goal`。

## 使用边界

持久草稿最多保留 32 份、合计 1 MiB；单个附件最多 64 KiB，最多 5 个，完整发送内容仍受 32,000 字符上限约束。存储失败时保留当前输入并提示，已有草稿不会被挤掉。

重启后可恢复对应会话草稿。尚未创建任务的 Code 草稿需回到原 Code 轨道和目录；切换轨道或打开目录会沿用尚未被任务占用的草稿身份，显式新建会话则创建新的身份。草稿存于当前设备，未实现跨设备同步。

差异使用现有检查点的整轮统一文本。备份清理、没有文本差异和已回滚分别显示提示；没有新增逐行编辑或文件级补丁操作。

后续仍需实际使用确认流式阅读和滚动、窄屏/主题布局及长附件展示。独立工作区、命令写盘边界、固定任务集和上下文质量评测仍在[下一阶段清单](next-todolist-20261026.md)，不需要等待视觉反馈才可继续推进这些工程能力。
